Daily Commit Compliance Reporting Tool

1. Overview
The Daily Commit Compliance Reporting Tool is an automated administrative solution designed to provide oversight of developer activity across multiple GitHub repositories. By integrating directly with the GitHub REST API and local SQL Server infrastructure, this engine automates the collection, aggregation, and reporting of commit data against localized work schedules to ensure organizational compliance.

2. Core Engine Architecture
The reporting engine utilizes a stateless, push-based architecture to minimize local dependencies.

API-Driven Data Pipeline: Instead of local repository clones, the engine utilizes the GitHub REST API (v3) to pull structured JSON payloads. This approach ensures a centralized, consistent view of organizational activity.

Data Aggregation: The script dynamically builds query URI targets based on the RepositoryRegistry and applies ISO-8601 UTC business-day window filters to reduce payload size and processing overhead.

SQL Server Integration: The engine cross-references Git activity against a localized SQL database (dbo.CompanyHolidays, dbo.RepositoryRegistry) to identify potential compliance gaps on corporate and federal holidays.

3. Operational Prerequisites
Before executing via SQL Server Agent, ensure the environment is configured to meet security and operational standards:

Security Context: The script relies on Windows DPAPI (Data Protection API) for encrypted credential storage.

SQL Proxy Configuration: To maintain the security context, the SQL Agent Job must be configured to run using a SQL Proxy mapped to the specific Windows user account that holds the credentials.

Credential Storage: Credentials must be pre-provisioned via Export-CliXml on the execution host using the account authorized by the SQL Proxy. Do not store credentials in plain text.

4. Deployment Steps
Developer Roster Setup: Execute 01_DeveloperRegistry.sql in SSMS to build the developer infrastructure registry.

Repository Registry Setup: Execute 02_RepositoryRegistry.sql in SSMS to provision the multi-repository tracking tables.

Holiday Reference: Execute 03_CompanyHolidays.sql in SSMS to populate the rolling federal lookup calendar.

SQL Agent Automation: Import the provided .ps1 script to the production directory. Create a SQL Agent Job using the PowerShell type, setting the job step to run as the configured SQL Proxy.

Execution Parameter: Set the job command to call the script with the production mode flag:

PowerShell
powershell.exe -ExecutionPolicy Bypass -File "C:\Scripts\DailyCommitReport.ps1" -Mode "2"
5. Enterprise Credential Governance
This tool is designed to adhere to "Encryption at Rest" standards:

No Plain-Text Secrets: All credentials are stored as encrypted XML files. The script utilizes Import-CliXml to decrypt these files into memory at runtime; they are never persisted to disk in clear text.

Credential Isolation: By executing via a SQL Proxy, the credentials remain tied to a specific user-profile security key. The SQL Server Agent Service Account never possesses the keys to decrypt the credentials, maintaining strict least-privilege boundaries.

Token Scoping: GitHub Personal Access Tokens (PATs) are restricted to read-only metadata permissions (repo:status, public_repo). Token rotation is managed administratively on a quarterly basis.

6. Troubleshooting & Audit Logs
If the job encounters failure, refer to the following:

Job History: Expand the SQL Agent Job History and select the failed step. The error message will identify if the failure is due to a permissions error or an authentication mismatch.

Permissions: Ensure the Windows user identity used by the SQL Proxy has Read access to the C:\Credentials folder and Write access to the output report directory (C:\Daily-Compliance-Reporting).

Credential Mismatch: If the job fails to authenticate, confirm that the credentials were generated by the same Windows user account defined in the SQL Proxy.

7. Future Roadmap (Enhancements)
Modern Auth Integration: Transition from SMTP relaying to Microsoft Graph API (OAuth 2.0) to align with evolving Exchange Online security requirements.

Automated Token Rotation: Integration with Azure Key Vault or similar secrets management services to automate the rotation of GitHub PATs.

Line-of-Code (LOC) Metrics: Integration of detailed statistical analysis to provide granular visibility into code additions and deletions.
